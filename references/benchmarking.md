# 验证与性能证据

只在任务涉及测试、baseline、benchmark 或 profiling 时加载。

- 新算子先明确语义、形状、dtype、布局、误差容限、正确性依据及验收要求；
  不要求存在旧实现或虚构性能基线。
- 优化比较必须明确基线和候选的精确源码状态。测试过的 commit 不证明后续修改有效。
- result 记录完整命令、工作目录、硬件与设备、驱动、固件、CANN、编译配置及关键依赖。
- 测量记录输入形状/分布、seed、预热、重复次数、同步方式、计时范围与原始样本。
- 比较必须使用兼容环境与测试条件；环境不同不能直接计算或声称加速。
- 正确性先通过才能接受性能结论；未测、失败或结果不确定分别说明。
- worktree 只隔离源码，不隔离 NPU、内存带宽、温度、电源模式或设备负载。
  同一测量资源默认串行使用；只有证明隔离有效后才允许并发性能测量。
- 不让多个 worktree 共写构建输出目录。复用缓存需确认版本、参数和并发安全。
- 关键日志与原始测量直接写入 Run 的 tests/、benchmarks/、profiling/ 等按需目录；
  临时路径中的有效证据在结束前收集，不能只给临时链接。
- result 可以汇总统计值，但必须链接原始文件；记录异常、失败和没有运行的验证。
- 没有可用设备时报告未验证，不伪造通过，也不将环境准备作为创建工作树的前提。
- 独立审计由不同 Worker 针对准确源码和已有证据执行，可作为同一 Variant 的新 Run。
- 代码集成后若源码状态变化，应重新做适用验证，不复用不再匹配的测试结论。
